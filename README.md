# walkthru

Walk a floor plan in first person, straight from an image. Zero
dependencies: the parser is Python stdlib, the client is one HTML file
with vanilla JS and canvas. Same plan, same walk, forever — nothing is
invented, every wall you see came from a dark pixel.

For anyone who needs to walk a space that does not exist yet (an
unbuilt house, a venue layout) or that they cannot visit, from nothing
more than a plan image.

## Play

```sh
python3 fixtures/gen_plans.py        # regenerate the demo plans
python3 -m walkthru.server 8000
# open http://127.0.0.1:8000/?plan=flat1.png
```

WASD to move (A/D strafe), arrow left/right to turn, M toggles the
menu. The menu loads any of the demo plans, uploads your own PNG
(parsed server-side, never persisted), and sets the plan's real-world
width in meters — areas and the HUD rescale instantly. The minimap
colors each detected room; the HUD shows the room you are standing in
and its measured area.

The renderer is fully textured — brick walls, wood doors, plank
floor, plaster ceiling — with textures generated procedurally in the
client (seeded, deterministic, zero assets). Movement is physical:
1.4 m/s walking pace (Shift to run), converted to grid cells through
the declared scale — a plan you declare as 48 m wide genuinely takes
four times longer to cross as one declared 12 m.

`fixtures/` holds two kinds of plans: synthetic demos generated by
`gen_plans.py`, and real-world sample plans (`house1.png`,
`house2.png`) contributed as-is to exercise the parser on annotated
drawings.

The scene JSON is a renderer-agnostic contract: metric scale, wall
height, occupancy grid, room membership, doors, and wall rectangles.
The 2.5D raycaster is one consumer of it; a WebGL/three.js client can
be added later against the same `/api/scene` without touching the
parser or server (a test pins this contract).

## How it works

- `walkthru/pngio.py` — minimal 8-bit PNG reader/writer (zlib +
  struct, defiltering included). Honest subset: gray/RGB/RGBA,
  non-interlaced; anything else is a clear error.
- `walkthru/plan.py` — the parser. Handles both polarities (dark lines
  on white paper or light lines on dark renders; "auto" picks the
  minority side as walls). Downsamples to an occupancy grid
  (block-minimum luma, so thin walls survive), detects doors as short
  floor runs whose jambs sit in a real wall — wall continuing past
  each jamb along the wall axis — which rejects the text and symbols
  covering real plans. Flood-fills rooms, extracts axis-aligned wall
  rectangles, and picks a spawn. Scale is a declared parameter
  (`plan_width_m`), because an image cannot prove its own size.
- `walkthru/scene.py` — Plan → compact deterministic JSON.
- `walkthru/server.py` — stdlib `http.server`, loopback by default;
  serves `www/` and `/api/scene?plan=<name>` (names resolve strictly
  inside `fixtures/`).
- `www/index.html` — the whole client: a textured DDA raycaster on
  canvas (Wolfenstein-style — a floor plan needs no mesh) with
  floor/ceiling casting, procedural seeded textures, distance shading,
  minimap, room HUD, and a menu (plan picker, PNG upload, scale).
- `fixtures/gen_plans.py` — deterministic demo plans (three layouts);
  fixtures are generated, never hand-edited.
- `tests/` — offline `unittest` suite; loopback-only. Asserts room and
  door counts against the known layouts, wall-rectangle coverage is
  exact and non-overlapping, scale math, byte-identical determinism,
  and server path handling.

## Tests

```sh
python3 -m unittest discover -s tests -v
```

## Status

Checkpoint 1 (MVP): floor-plan image → parsed rooms, doors, walls →
walkable first-person view with measured room areas. The walkthrough
engine is a 2.5D raycaster by design — grids are what floor plans
give you, and grids are what a raycaster eats.
